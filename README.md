# 환경경영 모니터링 대시보드

공공기관의 **온실가스·에너지·폐기물 실적을 한 화면에서 관리하는 웹 대시보드**입니다.
매달 숫자를 넣으면 배출량과 경영평가 점수가 자동으로 계산되고, 목표까지 얼마나 남았는지와
연말에 어디에 도착할지를 보여줍니다.

> 엑셀로 관리하던 것을 옮기려고 만들었습니다. 공공부문 온실가스 목표관리제 대상 기관이라면
> 화면 구성과 산식이 거의 그대로 맞습니다. 사업장·목표치·기준배출량·배출계수는
> 기관마다 다른데, 그 값들이 **`js/config.js` 한 파일에 모여 있습니다.**
> 다른 파일은 건드릴 필요가 없습니다.

**[→ 데모 보기](https://gmltks4240.github.io/nia-env-dashboard/)**

## 왜 만들었나

공공기관 환경경영 담당자는 매달 전기·가스·난방·차량연료·폐기물 사용량을 모아
배출량으로 환산하고, 경영평가 지표를 계산하고, 목표 대비 진척을 보고합니다.
대부분 엑셀 파일 여러 개를 오가며 수작업으로 하고 있습니다.

- 배출계수가 개정되면 과거 파일을 전부 찾아 고쳐야 합니다
- 사업장이 여러 곳이면 파일이 사업장 수만큼 늘어납니다
- 누가 언제 무슨 숫자를 바꿨는지 알 수 없습니다
- "이대로 가면 연말에 목표를 맞출 수 있나?"에 답하려면 또 따로 계산해야 합니다

이 도구는 그 네 가지를 없애는 것이 목표입니다.

## 무엇을 해주나

| 화면 | 하는 일 |
|---|---|
| **메인** | 경영평가 계량지표 점수(온실가스 60점 + 에너지 40점)를 실시간 계산. 점수가 왜 그렇게 나왔는지 산식까지 펼쳐서 보여줌 |
| **올해 현황** | 올해 사용량·배출량을 항목별·사업장별로. 작년 같은 기간과 비교 |
| **실적 조회** | 연도·사업장·항목으로 걸러서 과거 실적 조회 |
| **목표·로드맵** | 2050 중장기 감축 로드맵 대비 진척. 온실가스·RE100·폐기물 목표를 각각 추적 |
| **전망** | 남은 달을 추세로 예측해 연말 착지점을 추정. 목표 달성 가능 여부와 부족분 표시 |
| **데이터 입력** | 월별 숫자 입력. 한 달치를 한 번에 넣는 일괄 입력도 지원 |
| **데이터 관리** | 배출계수·목표치·사업장별 적용 항목 수정, 변경 이력, 사용자 권한 승인 |

**계산 근거**

- 온실가스 배출계수 — NGMS(국가온실가스종합관리시스템) 산정 실적 기반 유효계수
  (전력 0.0004594106 tCO₂eq/kWh, 도시가스 0.0021649672212 tCO₂eq/m³ 등)
  — **이 기관 실적에서 역산한 값이라 다른 기관은 자기 유효계수로 교체해야 합니다**
- TOE 환산계수 — 에너지법 시행규칙 [별표] 에너지열량 환산기준 (2022.11.21 개정)
- 폐기물 — 2024 시·도 폐기물 처리통계 기반 소각·매립 혼합 유효계수
- 계수는 모두 화면에서 고칠 수 있습니다. 개정되면 코드를 건드릴 필요가 없습니다

**그 밖에**

- 로그인 · 회원가입 후 관리자 승인 방식의 권한 관리 (보기 / 입력 / 관리)
- 모든 수정에 대한 변경 이력 — 누가 언제 무엇을 얼마에서 얼마로
- 냉난방도일(Open-Meteo)을 함께 보여줘 "추웠던 해라 많이 쓴 것"을 구분
- 다크 모드, 모바일 대응, 키보드 접근성

## 누가 쓸 수 있나

공공부문 온실가스 목표관리제 적용을 받는 기관이면 구조가 거의 같습니다.
사업장 목록, 목표치, 기준배출량, 배출계수를 바꿔서 쓰면 됩니다.

- 공공기관 · 지자체 · 공기업의 환경경영 / 총무 / 시설 담당
- 경영평가 계량지표(온실가스 감축률, 에너지 절감률)를 관리해야 하는 곳
- 사업장이 여러 곳이라 엑셀 취합이 번거로운 곳

## 설치

서버가 필요 없습니다. 정적 파일이라 GitHub Pages나 사내 웹서버에 올리면 끝이고,
데이터는 [Supabase](https://supabase.com) 무료 플랜으로 충분합니다.

**1. 내려받기**

```bash
git clone https://github.com/gmltks4240/nia-env-dashboard.git
cd nia-env-dashboard
```

**2. Supabase 프로젝트 만들기**

[supabase.com](https://supabase.com)에서 프로젝트를 만든 뒤, SQL Editor에서 아래 파일을
순서대로 붙여넣고 실행합니다.

```
supabase/auth_roles.sql       로그인·권한
supabase/phase2.sql           기타 지표·연도 마감·변경 이력
supabase/waste_multi_size.sql 폐기물 종량제 봉투 규격
supabase/who_changed.sql      (선택) 변경 이력에 이메일 대신 이름 표시
```

**3. 우리 기관에 맞추기 — `js/config.js` 한 파일만**

고쳐야 할 것이 전부 이 파일에 모여 있습니다. **다른 파일은 건드리지 마세요.**
그래야 나중에 업데이트를 받을 때 이 파일만 그대로 두면 됩니다.

| 항목 | 무엇 |
|---|---|
| `supabase` | 2단계에서 만든 프로젝트의 주소와 anon 키 (Project Settings → API) |
| `org` | 기관 이름·약칭·로고. 화면 제목과 머리글에 쓰입니다 |
| `sites` | 사업장 목록 — 이름·본사 여부·좌표·짧은 이름·전산실 여부·해당 없는 항목·폐기물 계수 |
| `targetSites` | 어느 사업장에 어느 목표(온실가스·RE100·폐기물)를 적용하는지 |
| `ghgBase` | 연도별 기준배출량 (목표관리제 통보값) |
| `roadmap` | 자체 감축 로드맵. 없으면 `[]` 로 두고 화면에서 입력 |
| `factors` | 배출계수 — **기관마다 다릅니다.** 본인 기관 NGMS 유효계수로 교체 |
| `solar` | 태양광 설비. 없으면 `[]` |
| `evaluation` | 경영평가 배점·기준연도 |

사업장을 바꾸면 화면의 사업장 단추·설명·목표 안내 문구가 **자동으로 따라갑니다.**
손으로 고칠 곳이 따로 없습니다.

`ghgBase`·`roadmap`·`factors`·`solar` 는 **기본값**입니다. 데이터 관리 화면에서
한 번이라도 저장하면 그 값이 기본값을 덮어씁니다. 운영 중이라면 코드보다
화면에서 고치는 쪽이 맞습니다.

**4. 사업장 색 (사업장이 4곳 이상이면)**

`css/app.css` 의 `--chart-site-*` 토큰에 색을 추가하고,
`js/config.js` 의 각 사업장 `color` 에 그 토큰 이름을 적습니다.
3곳 이하면 그대로 두면 됩니다.

**5. 띄우기**

```bash
python3 -m http.server 8000
```

브라우저에서 `http://localhost:8000` 을 엽니다.
사내 배포는 이 폴더를 그대로 웹서버에 올리거나 GitHub Pages를 켜면 됩니다.

## 개발

```bash
pip install playwright==1.65.1 && playwright install chromium   # 처음 한 번 (CI와 같은 버전)
python3 tests/run_all.py                                 # 테스트
python3 tools/bump_version.py                            # css·js 고친 뒤 꼭 실행
```

`bump_version.py` 는 `index.html` 의 `?v=` 를 파일 해시로 바꿉니다.
안 돌리면 사용자 브라우저가 캐시된 옛 파일을 계속 씁니다.

**구조**

```
index.html      화면 뼈대 · SVG 아이콘
css/app.css     스타일 (디자인 토큰 기반)
js/config.js    우리 기관 설정 ← 다른 기관은 이 파일만 고치면 됨
js/core.js      상수 · 계산 · Supabase · 로그인
js/ui.js        토스트 · 확인창 등 공통 부품
js/charts.js    Chart.js 설정
js/home.js      메인 · 경영평가 점수
js/dashboard.js 올해 현황 · 실적 조회
js/outlook.js   목표·로드맵 · 전망
js/input.js     데이터 입력
js/manage.js    데이터 관리 · 변경 이력
js/main.js      탭 이벤트 · boot()  ← 반드시 마지막에 로드
```

빌드 도구가 없습니다. 파일을 고치고 새로고침하면 바로 보입니다.

- [`AUDIT.md`](AUDIT.md) — 코드 구조 점검 기록
- [`DESIGN-REVIEW.md`](DESIGN-REVIEW.md) — 디자인 시스템 결정 사항
- [`CONTRIBUTING.md`](CONTRIBUTING.md) — 함께 개발하는 방법
- [`docs/decisions/`](docs/decisions/) — 되돌리기 어려운 결정과 그 이유
  (001: 공개 범위를 어디까지 둘지)
