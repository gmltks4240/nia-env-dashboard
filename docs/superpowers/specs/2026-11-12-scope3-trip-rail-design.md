# Scope 3 출장 배출량 자동산정 — 1단계(철도) 설계

- 작성일: 2026-11-12
- 상태: 1차 구현 완료 (구현하며 바뀐 점은 §11)
- 용도: **대외 공시·검증 대응** (행 단위 추적, 가정·제외 항목 문서화 필요)

## 1. 목표

출장 엑셀을 올리면 자유 입력된 출발지·목적지를 AI가 표준 지점으로 분류하고,
정해진 규칙으로 Scope 3 카테고리 6(출장) 배출량을 산정해 대시보드에 표시한다.

성공 기준:

1. 관내출장 엑셀(연도별 시트)을 올리면 철도 행 전체가 행 단위로 산정된다.
2. 모든 행에 판정 등급(A~D)·적용 거리·계수·근거가 남아 한 건씩 추적할 수 있다.
3. 같은 파일을 다시 올리면 같은 결과가 나온다(AI 결과는 사전에 고정).
4. AI 호출이 실패해도 산정이 멈추지 않는다.
5. 산정 엔진이 2026-11-12 시산값(§9)을 재현한다.

## 2. 범위

| 단계 | 내용 | 이 문서 |
|---|---|---|
| 1단계 | 업로드 → 장소 사전(AI) → 철도 산정 → Scope 3 화면·검토 화면 | 대상 |
| 2단계 | 자가차량, 국내 항공, 버스, 선박 | 대상 아님 (계수 협의 필요) |
| 3단계 | 국외 항공 | 대상 아님 (계수·경유지 기준 협의 필요) |

장소 사전·행별 저장·업로드 묶음·검토 화면은 교통편에 묶이지 않게 만들어 2·3단계에서 재사용한다.

1단계에서 하지 않는 것: 숙박 배출, 철도 외 교통편 산정, 좌석 등급별 계수.

## 3. 확정된 산정 규칙

사용자와 합의한 내용이다.

### 3.1 경계

- GHG Protocol Scope 3 카테고리 6(출장).
- 공용차량은 제외한다(연료가 Scope 1 차량연료에 이미 포함).
- 차량동승은 0으로 본다(운전자 행에 포함).

### 3.2 행의 의미

- 한 행 = 출장 1건(1인). 출발지→목적지는 가는 방향만 적은 것이고 기본은 왕복이다.
- 한 출장의 철도 이동은 **왕복 1회가 상한**이다(174,000원·121,800원도 왕복 1회).
- 교통비가 구간 왕복 운임의 절반 수준이면 편도다.
- **교통비 0원은 미이동**으로 보고 제외한다. 제외 건수는 따로 집계해 공시 주석에 쓴다.
- "서울→서울"에 대구–서울 편도 운임이 찍힌 행은 동대구→서울 편도 1회다(선이동 관행).
- 특실은 임원 등 극히 일부가 이용한다. 계수는 좌석 등급을 구분하지 않으므로
  특실 운임은 편도/왕복 판정에만 쓴다.

### 3.3 철도 배출계수 (기관 협의값)

| 구분 | kgCO₂eq/인·km | 적용 |
|---|---|---|
| KTX 경부선 | 0.0219 | 기본 |
| KTX 호남선·기타 | 0.0219 | 경부선 준용 |
| KTX 강릉선 | 0.0716 | 출발지·목적지가 강릉·평창·진부·횡성·둔내 권역일 때 |
| SRT | 0.0219 | 별도 인증계수 확인 전 대용 |

열차 종류는 파일에 없다. KTX·SRT·일반열차를 구분하지 않고 0.0219를 쓰며,
원주·춘천은 강릉선이 아닌 것으로 본다.

### 3.4 거리

- 한국철도공사 철도운행거리(2024-09-01) 정규화 1,412행을 쓴다.
- 같은 역쌍에 거리가 여럿이면 표1(고속선 대표 경로)을 쓴다. 동대구–서울 286.7km.
- 수서 구간은 코레일 원본에 없어 참고값을 쓴다(수서–동대구 269.2, 수서–서대구 261.8).
  그 외 수서–X는 서울–X − 17.5km, 서대구–X는 동대구–X ± 7.4km로 추정하고 "거리 추정"으로 표시한다.

### 3.5 판정 등급

행마다 아래 순서로 판정하고 등급을 남긴다.

| 등급 | 조건 | 거리 |
|---|---|---|
| A 업무상 확정 | 교통비가 판정기준표(`출장운임_판정기준` 14개 운임)와 일치 | 판정기준표의 거리 |
| B 운임표+구간 일치 | 교통비가 운임표의 편도 운임 또는 같은 도시쌍 두 구간 합과 일치하고, 장소 사전으로 얻은 출발·목적 도시가 그 구간과 일치 | 해당 구간 공식거리 |
| C 운임표만 일치 | 교통비는 운임표와 일치하나 출발·목적 도시로 구간을 확인하지 못함. 후보 거리 편차 5% 이내일 때만 | 후보 구간 거리 |
| D 추정 | 위에 해당 없음. 출발·목적 도시의 구간이 있으면 그 공식거리를 쓰고, 교통비가 기준 편도 운임의 1.5배 미만이면 편도·이상이면 왕복. 구간도 모르면 교통비 ÷ 151.7원/km(43,500 ÷ 286.7), 상한 860km | 구간 거리 또는 운임 역산 |

보조 규칙:

- 특실 운임 = KTX 일반실 × 1.4, 100원 단위 반올림. 파일 수치(43,500 → 60,900)로 확인한 산식이며
  공식 특실 운임표와의 대조는 미완료다. 후보가 여럿이면 일반실 > 특실, 공식거리 > 추정거리, KTX > SRT 순으로 고른다.
- 판정기준표의 편도 운임(SRT 36,900~37,300, 오송 환승 43,300)은 두 구간 합 계산의 재료로도 쓴다
  (예: 80,400 = 43,500 + 36,900).
- 목적지·경유지가 여러 도시면 D등급에서는 가장 먼 구간을 쓴다.
- 강릉선 권역 행은 구간 거리표가 없어 운임 역산(D)으로 처리한다.

## 4. 구성요소

각 단위는 하나의 일만 하고, 아래 인터페이스로만 이어진다.

### 4.1 업로드·파싱 (브라우저)

- 기존 엑셀 업로드(SheetJS 지연 로딩)를 재사용한다.
- 출장 양식을 인식한다: 시트 제목 `관내출장현황`, 머리글 3행, 열 = 번호·시작일·종료일·박·일·출발지·경유지·목적지·교통편·왕복거리·연비·유가·교통비.
- 출력: `TripRow[]` = `{ year, seq, date, origin, via, dest, mode, fare, distKm, fuelEff, fuelPrice }`.
- 1단계는 `mode === '철도운임'`만 산정하고, 나머지 교통편은 건수만 "미산정"으로 집계한다.

### 4.2 장소 사전 (Supabase `trip_places`)

원문 장소명을 표준 지점으로 바꾼 결과를 고정 저장한다.

| 열 | 설명 |
|---|---|
| `raw` (PK) | 앞뒤 공백을 지운 원문 |
| `points` | 표준 지점 코드 배열. 복수 목적지("세종, 서울")는 여러 개 |
| `confidence` | `high` / `low` / `unknown` |
| `reason` | 한 줄 근거 |
| `source` | `seed`(사전 탑재) / `ai` / `human` |
| `updated_by`, `updated_at` | 변경자·시각 |

- 표준 지점 코드는 도시 단위다: 대구, 서울, 세종(오송), 대전, 부산, 천안아산, 김천구미, 경주, 울산, 포항,
  광주송정, 나주, 익산, 전주, 목포, 여수, 순천, 진주, 창원, 밀양, 공주, 정읍, 강릉선권역, 제주, 기타.
  도시→역 대응(서울 = 서울·용산·광명·수서 등)은 산정 엔진이 가진다.
- `source = human`인 행은 AI가 덮어쓰지 않는다.
- 초기 데이터: 현재 4개 연도의 고유 장소 3,513개를 분류해 `seed`로 넣는다.

### 4.3 AI 분류 함수 (Supabase Edge Function `classify-places`)

- 입력: 사전에 없는 원문 장소명 배열(한 번에 최대 100개).
- 처리: Claude API에 표준 지점 코드 목록을 주고, 장소마다 `points`·`confidence`·`reason`을 구조화 출력으로 받는다.
  목록에 없는 값은 거부하고 `unknown`으로 처리한다.
- 출력: `trip_places`에 `source = ai`로 기록하고 결과를 돌려준다.
- 권한: 로그인한 편집자·관리자만 호출할 수 있다(`app_role()` 확인).
- API 키는 Supabase 비밀값으로만 둔다. 화면 코드에는 넣지 않는다.
- 전송 내용은 장소명 문자열뿐이다(번호·날짜·금액·부서 미전송).
- 키가 없거나 호출이 실패하면 오류 코드를 돌려주고, 화면은 해당 장소를 `unknown`으로 두고 계속한다.

### 4.4 기준표 (Supabase `trip_ref`)

판정에 쓰는 표를 적용 기간과 함께 저장한다.

| 열 | 설명 |
|---|---|
| `kind` | `judgment`(판정기준) / `fare`(운임표) / `distance`(거리표) |
| `valid_from`, `valid_to` | 적용 기간. 출장 시작일로 고른다 |
| `data` | 표 내용(jsonb) |
| `source_note` | 출처·기준 시점 |
| `version` | 버전 문자열 |

- 초기 데이터: 판정기준 14행, KTX 주요 운임 21행, SRT 일반실 505행, 공식 운행거리 1,412행, 수서 참고거리.
- 2026-09-01 이후 운임 개편분은 새 기간의 `judgment`·`fare`로 추가한다(자료 확보 전에는 해당 행이 D등급으로 남는다).
- 철도 계수는 기존 `env_settings.ghg_factor_log`에 항목을 추가해 변경이력을 함께 쓴다.

### 4.5 산정 엔진 (브라우저, 순수 함수)

```
classifyRail(row, places, ref, factors)
  → { grade, legs, km, kmQuality, factor, kgCO2e, basis }
```

- 입력만으로 결과가 정해진다. 네트워크·시각·난수를 쓰지 않는다.
- §3.5의 순서를 그대로 구현한다. AI는 `places`를 통해서만 영향을 준다.
- `basis`는 사람이 읽는 한 줄 근거다(예: `KTX 동대구↔오송 왕복 일반`).

### 4.6 저장 (Supabase)

- `trip_batches`: 업로드 묶음. 파일명, SHA-256, 연도, 올린 사람, 적용한 기준표·계수 버전, 등급별 건수.
- `trip_rows`: 행별 결과. 원본 값 전체 + `points_origin`, `points_dest`, `place_source`, `grade`, `legs`, `km`, `factor`, `kgco2e`, `basis`, `batch_id`.
  0원 제외 행과 미산정 교통편 행도 `grade = 제외`/`미산정`으로 남긴다.
- 같은 연도를 다시 올리면 이전 묶음의 행을 지우고 새 묶음으로 대체한다(묶음 기록은 남긴다).
- 월별 집계는 `env_metrics`에 넣는다: `period = YYYY-MM`, `site = 전사`, `item = 출장_철도_kgCO2e` / `출장_철도_인km`.
  마감연도 차단·변경이력·내보내기가 기존대로 동작한다.
- 읽기는 기존 정책과 같고, 쓰기는 편집자·관리자만 가능하다.

### 4.7 화면

- **Scope 3 카드**: 폐기물 옆에 출장(철도)을 추가한다. 값 아래에 등급 비율(확정·일치·추정)을 함께 표시한다.
- **근거 패널**: 교통편별 인·km, 계수, 배출량, 산식, 제외 건수.
- **데이터 입력 탭**: 출장 엑셀 업로드. 올리면 "새 장소 n개 분류 중 → 산정 → 요약" 순서로 진행을 보여 준다.
- **검토 화면**(데이터 관리 탭): 세 목록.
  1. 확신 낮음·미확인 장소 — 표준 지점을 고르면 `source = human`으로 저장하고 영향 받는 행을 다시 산정한다.
  2. D등급 행 — 운임별로 묶어 건수 순으로 보여 준다.
  3. 제외된 0원 행 건수(연도·월별).
- 행별 결과 CSV 내보내기.

## 5. 데이터 흐름

1. 엑셀 선택 → 파싱 → `TripRow[]`
2. 철도 행의 고유 장소명 추출 → `trip_places` 조회 → 없는 것만 `classify-places` 호출
3. `trip_ref`·계수 로드 → 행마다 `classifyRail`
4. 요약 미리보기(연도별 건수·등급 비율·배출량) → 사용자가 저장 확인
5. `trip_batches`·`trip_rows`·`env_metrics` 저장 → Scope 3 화면 갱신

## 6. 오류 처리

| 상황 | 동작 |
|---|---|
| 양식이 다름(머리글 불일치) | 저장하지 않고 어떤 열이 없는지 알려 준다 |
| AI 함수 실패·키 없음·시간 초과 | 해당 장소를 `unknown`으로 두고 산정을 계속한다. 검토 목록에 올린다 |
| AI가 목록 밖 값을 답함 | `unknown`으로 처리한다 |
| 마감연도에 업로드 | 기존 마감 차단 메시지를 그대로 보여 준다 |
| 저장 중 일부 실패 | 묶음을 실패로 표시하고 이전 묶음을 유지한다(행 삭제는 새 묶음 저장 성공 뒤) |
| 날짜·금액이 숫자가 아님 | 그 행을 `미산정`으로 남기고 건수를 요약에 표시한다 |

## 7. 테스트

- **산정 엔진**: 화면 없이 함수만 검증한다(`test_forecast.py` 방식). 등급별 대표 사례 —
  87,000(A 왕복), 43,500 서울→서울(A 편도), 49,600 대구→세종(B), 80,400(B, KTX+SRT),
  60,900(특실 편도), 174,000(왕복 상한), 0원(제외), 강릉(0.0716), 미확인 장소(C/D).
- **회귀 기준값**: §9의 연도별 건수·거리·배출량을 고정 표본으로 재현한다.
- **AI 함수**: 테스트에서 가짜 응답으로 대체한다(기존 Supabase mock). 실패 응답 때 산정이 계속되는지 확인한다.
- **화면**: 업로드→요약→저장 흐름, 검토 화면에서 사람 확정 후 재산정.

## 8. 배포 시 사용자가 할 일

- Supabase에 SQL(`supabase/trip_scope3.sql`) 실행.
- Anthropic API 키를 Supabase 비밀값으로 등록하고 Edge Function 배포. 그 전까지는 사전 탑재분만으로 동작한다.
- 장소명을 외부 AI로 보내는 것이 기관 정책에 맞는지 확인.

## 9. 시산 기준값 (2026-11-12, 검토용 스크립트)

장소 분류를 키워드 규칙으로 한 1차 시산이다. AI 사전을 적용하면 B·C·D 비율이 달라질 수 있어,
회귀 테스트는 같은 장소 사전을 고정해 비교한다.

## 10. 미해결 사항

구현을 막지는 않지만 정확도에 영향을 준다. 해결 전에는 해당 행이 D등급으로 남는다.

1. **46,900원, 대구→세종(약 1,450건)**: 운임표 조합과 맞지 않는다. 현재 동대구↔오송 왕복 324km로 추정.
2. **2026-09-01 이후 운임 개편**: 9~10월 2,652건 중 A등급 102건. 새 운임 기준의 판정표·운임표가 필요하다.
3. **KTX 전 구간 운임표**: 현재 핵심 21개뿐이다. 원본(`Fare_Table_190830_KTX.xls`, `KTX-요금표.xls`) 확보 시 반영.

5. **판정규칙 승인**: 시산 파일의 `판정규칙_승인용` 356개 규칙 검토 결과를 판정기준표에 반영.

## 11. 구현하며 바뀐 점 (2026-11-12)

- **기준표 위치(§4.4)**: `trip_ref` 테이블 대신 `index.html` 안의 `@trip-ref` 블록에 둔다(`tools/build_trip_ref.py`로 생성, 버전 포함). 대시보드는 `index.html` 하나만 올려도 돌아가야 해서 따로 파일로 두지 않는다.
  git 이력이 변경 기록이 되고, SQL 실행 전에도 미리보기가 동작한다. 기간별 운임표(2026-09 이후)는 아직 넣지 않았다.
