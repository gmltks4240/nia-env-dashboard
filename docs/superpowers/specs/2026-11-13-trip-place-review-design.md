# 출장 장소 AI 분류와 검토표 — 짧은 설계

- 작성일: 2026-11-13
- 상태: 대화에서 승인 ("그렇게하자")
- 앞선 설계: `2026-11-12-scope3-trip-rail-design.md` (§4.2 장소 사전, §4.3 AI 분류 함수)

## 왜 하는가

출장 엑셀을 올리면 "분류하지 못한 장소 687개"가 남고, 사람이 하나씩 지점을 골라야 한다.
담당자는 이것을 AI가 대신하길 원하고, **AI가 낸 결과에 오분류가 없는지 직접 확인**할 수 있어야 한다.
대외 공시용이라 "AI가 그렇게 답했다"만으로는 근거가 되지 않는다.

담당자가 정한 기준: **목적지를 보고 구분이 안 되면 운임과 대조한다.**

## 확인한 사실 (2026-11-13, 4개 연도 파일)

- 지금 화면에서는 AI가 돌지 않는다. 분류는 키워드 규칙이고, AI 함수는 API 키·배포가 없어 꺼져 있다.
- 유료 철도 65,430건의 고유 장소는 2,305개. 규칙으로 분류 1,618개, 미분류 687개.
- 미분류 장소가 낀 출장은 1,674건(2.6%). 분류에 따라 결과가 바뀔 수 있는 것은 997건, 9.2t(4년 합계 642.6t의 1.4%).
- 미분류 687개 중 576개는 1~2건짜리다. 3건 이상인 111개가 등장 횟수의 62%를 차지한다.
- 규칙 분류를 운임으로 대조하면 운임 증거 85,985건 중 96.1%가 규칙 결과와 일치한다.

## 목표

1. 지금 있는 미분류 장소를 사람 손 없이 분류한다.
2. 앞으로 새 파일에 처음 나오는 장소도 자동으로 분류한다(API 키가 준비되면).
3. 모든 분류(사람·AI·규칙)를 한 표에서 보고, 운임과 대조해 의심스러운 것부터 고칠 수 있다.

## 하지 않는 것

- 자체 AI 모델 학습.
- 운임으로 장소를 자동 지정하는 것(아래 "운임의 역할").
- 장소 사전 전체를 관리하는 별도 화면(검색·일괄 수정). 올린 파일에 나온 장소만 검토표에 보인다.
- 규칙으로 분류된 장소를 AI가 전부 다시 분류하는 것. AI 함수가 실제로 검증된 뒤에 정한다.

## 이렇게 되면 실패

- AI가 틀린 분류를 조용히 넣고, 담당자가 그것을 찾을 방법이 없다.
- 같은 파일을 다시 올렸는데 결과가 달라진다.
- 행별 출장 기록이나 장소명이 로그인 없이 읽힌다.

## 검토한 방법

| 방법 | 내용 | 판단 |
|---|---|---|
| A. AI 함수(Claude API) | 업로드할 때 새 장소를 자동 분류 | 채택(이미 작성됨). API 키·배포 필요 |
| B. 이 대화에서 한 번 분류 | 지금 있는 장소를 AI가 분류해 사전 파일로 전달 | 채택. API 키 없이 지금 가능. 앞선 설계 §4.2의 "초기 데이터" |
| C. 자체 모델 학습 | 분류 모델을 직접 학습 | 기각. 학습 데이터·운영 부담이 드는데 처음 보는 기관명·오타에 더 약함 |
| D. 운임으로 장소 지정 | 교통비가 가리키는 지역을 그 장소의 분류로 사용 | 기각. 등급 B가 자기 자신을 확인하게 됨 |

B로 시작하고 A를 켠다(앞선 설계의 C안 그대로).

## 정한 것

### 분류의 우선순위

사람 확정 → AI(장소 사전) → 키워드 규칙 → 없음.

장소를 정하지 못하면(없음·AI "모름") 그 행은 **운임만으로 판정**한다(등급 C 또는 D). 이것이 "구분이 안 되면 운임과 대조"의 계산 쪽 구현이며, 지금 엔진이 이미 그렇게 동작한다.

### 운임의 역할: 지정이 아니라 대조

- 장소 P로 간 출장들의 교통비가 판정기준표·운임표의 어느 구간과 같은지 모아, "운임이 가리키는 곳"을 장소마다 집계한다.
- 반대편 장소의 도시를 알고, 두 도시가 서로 다르고, 분류된 도시와 반대편 도시 사이에 운임표 구간이 있을 때만 증거로 센다. 경유지는 쓰지 않는다.
- 분류와 비교해 표시한다: `일치`(증거의 절반 이상이 분류와 같음), `다름`(증거 3건 이상인데 절반 미만), `다름(건수 적음)`(증거 1~2건), `대조 불가`(증거 없음), `참고`(지점이 없는 장소에 운임 증거만 있음).
- `다름`은 "틀렸다"가 아니라 "먼저 볼 곳"이다. 운임표에 없는 구간이거나 다른 곳에서 탄 경우에도 나온다.
- 운임 증거로 장소를 자동 지정하지 않는다. 지정은 사람이 검토표에서 한다.

### 검토표 (화면)

"분류하지 못한 장소" 표를 "장소 분류 검토" 표로 바꾼다. 올린 파일의 유료 철도 행에 나온 장소가 대상이다.

```
장소            출장  분류    출처  확신  이유                 운임이 가리키는 곳  운임 대조  고치기
한국프레스센터    53   서울    AI    높음  서울 중구의 건물      서울 50건          일치      [지점 ▾]
경북센터          8   모름    AI    —     어느 기관인지 모름    부산 1 · 대전 1     참고      [지점 ▾]
```

- 정렬: `다름` → 미분류 → AI "모름" → 확신 낮음·`다름(건수 적음)` → 나머지, 각 안에서 출장 건수 순.
- 보기: 확인 필요(기본) / AI 분류 / 규칙 분류 / 사람 확정 / 전체. 화면에는 100개까지, 전체는 CSV로.
- 지점을 고르면 `사람 확정`으로 장소 사전에 남고 바로 다시 계산한다. "기타"는 "거점 없음"이다.

### AI 분류 (함수)

- 규칙으로 못 푼 장소 중 사전에 없는 것만 보낸다. 장소명 문자열만 보낸다.
- AI가 "모름"이라고 답한 것도 사전에 남겨 다시 묻지 않는다. 검토표의 "확인 필요"에 나온다.
- 한 번에 50개씩, 동시에 3묶음. 실패하면 남은 묶음을 멈추고 규칙만으로 계속한다. 다음 업로드 때 남은 것만 다시 보낸다.
- 지점 기준을 프롬프트에 적는다: 수도권은 서울(단 SRT 동탄·평택지제 권역은 거점 없음), 세종청사 부처·청주·오송은 세종, 경산은 대구, 원주·춘천 등 거점이 없는 곳은 "기타".

### 초기 사전 (이 대화에서 분류)

- 대상: 미분류 687개 전부와, 규칙이 잘못 본 장소(키워드 충돌)의 정정.
- 장소 이름만 보고 분류한다. 운임 증거는 분류한 뒤 대조에만 쓴다(대조가 독립적이어야 의미가 있다).
- `source = 'ai'`, `updated_by = 'claude-session-2026-11-13'`로 넣는 SQL 파일과, 같은 내용의 검토용 엑셀을 담당자에게 전달한다.
- 원본 장소명이 들어 있으므로 저장소에는 커밋하지 않는다.

### 읽기 권한

- `trip_rows`(행별 기록)와 `trip_places`(장소 사전)는 로그인한 입력·수정·관리자만 읽는다.
- `trip_batches`(연도별 요약)는 누구나 읽는다. 올해 현황 카드가 로그인 없이도 보여야 하기 때문이다.
