# 003. 출장 분석 도구 3개를 `tools/trip.py` 하나로 합친다

날짜: 2026-11-26

## 무엇을 정했나

따로 있던 분석 도구 3개를 **`tools/trip.py` 의 세 기능(`eval` · `verify` · `sample`)** 으로 합쳤다.

| 전 | 후 |
|---|---|
| `tools/eval_trip.py` 154줄 | `python3 tools/trip.py eval <xls>` |
| `tools/verify_trip.py` 138줄 | `python3 tools/trip.py verify <xls>` |
| `tools/sample_trip.py` 149줄 | `python3 tools/trip.py sample <xls> --out 표본.csv` |
| **441줄 · 3파일** | **336줄 · 1파일** |

기능은 하나도 줄이지 않았다. 생성 도구(`build_trip_ref` · `build_trip_fares` · `build_trip_seen`)는
각각 다른 엑셀을 읽어 다른 블록을 쓰므로 **합치지 않고 그대로 뒀다.**

## 그때 상황

사용자가 "파일이 너무 많은데 저렇게 구분되어 있는 이유가 있나?" 라고 물었다. 세어 보니 출장 전용
파일이 20개였다. 하나하나 따져 보니 **셋으로 갈렸다.**

- **근거가 확실한 것** — `js/trip-data.js`(94KB 생성물, 도구가 덮어씀) ·
  `js/trip-engine.js`(테스트·도구가 통째로 읽어 브라우저에 넣음) · `js/trip-ui.js` ·
  테스트 2개(엔진은 빈 페이지, 화면은 대시보드를 띄움 — 돌리는 방식이 다름). **합치면 깨진다**
- **문서 7개** — main 의 규칙이 "개발 과정 자체가 평가 대상" 이라 남기는 게 맞다
- **중복** — 분석 도구 3개. 이건 **내가 급하게 하나씩 만들면서 공통 부분을 빼지 않은 것이다**

중복을 실제로 셌다:

- 엑셀 읽고 머리글 찾는 부분 — **3번** 베껴 있었다
- 엑셀 날짜 일련번호 변환(`1899-12-30` 기준) — **3번**
- 브라우저 띄워 엔진 올리는 부분(`tripBuildRef`) — **4번**(생성 도구 포함)

## 왜 지금 했나 — 실제로 터진 문제

2026-11-23 에 사용자가 두 번째 엑셀을 줬다. `번호` 칸이 없고 `출장시작일` 이 머리글 아랫줄에 있는
양식이라 **63,593행이 모두 걸러져 "출장 행이 없어요"** 가 났다. 엔진 파서는 한 곳만 고쳐 끝났지만,
같은 양식 처리가 도구 3곳에 흩어져 있어 **양식이 또 바뀌면 3곳을 고쳐야 하는 상태**였다.
합치는 이유는 파일 수가 아니라 **고칠 자리가 하나여야 한다는 것**이다.

## 고려한 선택지

### A. 그대로 둔다

파일마다 독립이라 하나 고장 나도 다른 게 안 멈춘다. 대신 양식이 바뀔 때마다 3곳.

### B. 공통 부분만 모듈로 빼고 파일 3개는 유지

`tools/_trip_common.py` 같은 것을 만든다. 중복은 없어지지만 **파일이 4개로 늘어난다.**
사용자가 줄이고 싶어 한 것은 파일 수이기도 했다.

### C. 한 파일에 세 기능(하위 명령) ← **고름**

`git`·`docker` 처럼 `trip.py eval|verify|sample`. 공통 부분이 한 번만 쓰이고 파일도 1개다.

## 고른 이유

1. **고칠 자리가 한 곳이 된다** — 엑셀 양식·엔진 띄우기가 `load_rail()` 과 `Engine` 한 쌍뿐이다
2. 세 기능이 **같은 입력(관내출장 엑셀)과 같은 엔진**을 쓴다. 한 덩어리로 묶이는 것이 자연스럽다
3. 도구는 **대시보드가 쓰지 않는 코드**라, 깨져도 사용자 화면에 영향이 없다. 합치는 위험이 작다

## 합치면서 발견해 고친 것 (중요)

합친 뒤 옛 도구와 숫자를 맞춰 봤더니 **총 배출량이 495.3t → 492.9t 로 2.4t 어긋났다.**
등급 건수는 똑같았는데 거리만 달랐다.

원인: 옛 도구는 엔진의 `tripParseSheet` 로 엑셀을 읽어, **출장일수 칸이 비면 시작일·종료일로
일수를 계산**해 주었다. 새 로더는 출장일수 칸만 읽어 그 경우 `None` 이 됐다.
일수는 **왕복 n회 판정에 쓰여 거리를 바꾼다** — 그래서 총량이 달라졌다.

`load_rail()` 에 같은 규칙(일수 → 없으면 시작·종료일 간격 → 그래도 없으면 None)을 넣어 고쳤고,
코드에 "어긋나면 총 배출량이 달라진다" 는 주석을 남겼다.

**교훈**: 도구를 합칠 때 "기능이 같다" 로 끝내면 안 되고 **같은 입력에 같은 숫자가 나오는지** 봐야 한다.

## 검증

옛 도구와 새 도구를 같은 엑셀(2024~2026, 철도 54,098행)로 돌려 비교했다.

| | 옛 도구 | `trip.py` |
|---|---|---|
| 연도별 등급·만km·tCO₂e | 2,260.8만km · **495.3t** | **완전히 같음** |
| verify — 방문처 어긋남 | 60행 (0.22%) | 같음 |
| verify — 장소 셔플 | 70.4% → 13.6% | 같음 |
| verify — 금액 흔들기 | +100원 34,640 유지 / 1,019 거리 바뀜 | 같음 |
| sample — 뽑힌 30행 | — | **30/30 동일** |
