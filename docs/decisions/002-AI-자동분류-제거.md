# 002. 출장 장소 분류에서 AI 자동 호출을 뺀다 — 사전 기반으로 간다

날짜: 2026-11-26

## 무엇을 정했나

출장 엑셀을 올릴 때 **Claude API 를 불러 새 장소를 자동 분류하던 경로를 지운다.**
장소 분류는 **사전(`trip_places`) 기반**으로만 간다.

지운 것:

| 대상 | 분량 |
|---|---|
| `supabase/functions/classify-places/index.ts` | 133줄 (파일 전체) |
| `js/trip-ui.js` 의 `tripAskAI` · 호출부 · `aiNote` 안내 | 약 33줄 |
| `tests/test_trip_ui.py` 의 "AI 분류"·"AI 모름"·"AI 묶음" 3블록 | 약 60줄 |

남긴 것 — **사전 기반이 쓰는 것은 그대로다**:

- `tripLoadPlaces` — `trip_places` 에서 사전을 읽어 적용
- `tripSetPlace` — 사람이 지점을 확정하면 `source='human'` 으로 사전에 저장
- 검토표의 **출처 'AI' 표시** — 사전에 들어 있는 739개가 `source='ai'` 다.
  AI 가 분류했다는 사실은 그 자료의 내력이므로 표시는 남아야 한다
- `tests/harness.py` 의 Edge Function 가로채기 — 이제 **"유료 API 를 부르지 않는다"를
  증명하는 장치**로 쓴다. `mock.calls == []` 를 테스트가 단정한다

## 그때 상황

사용자가 "유료라서 안 하기로 했던 것 같은데?" 라고 물었다. 문서를 확인했더니 **기억이 거의 맞지만
적힌 이유가 달랐다.**

- `docs/HANDOFF-trip-scope3.md` — "**AI 자동 호출은 쓰지 않기로 함**", "**배포하지 않기로 함**".
  **이유가 안 적혀 있었다**
- `docs/superpowers/specs/2026-11-13-trip-place-review-design.md` — "AI 함수는 **API 키·배포가 없어
  꺼져 있다**", "앞으로 새 파일에 처음 나오는 장소도 자동으로 분류한다(**API 키가 준비되면**)".
  선택지 표에는 A(AI 함수)·B(대화에서 한 번 분류) **둘 다 '채택'** 으로 적혀 있었다

즉 문서상으로는 "**키가 없어 보류**" 였고, "유료라서 안 한다" 는 **대화에만 있고 기록에 없는 결정**이었다.
CLAUDE.md 가 경고한 바로 그 상태다 — "같은 결정이 뒤집힌 적이 있어 경위를 적어 두지 않으면 또 뒤집힌다".
그래서 이번에 이유를 못 박아 둔다.

사실 관계:

- Claude API 는 유료다(쓴 만큼 과금). `ANTHROPIC_API_KEY` 가 필요하다
- 규모는 작다 — 고유 장소 2,305개 중 규칙이 못 푼 **687개**. 장소 이름만 보내고 분류만 받는다.
  한 번 분류하면 사전에 저장돼 다시 묻지 않는다. **반복 비용이 아니라 거의 일회성**이다
- 그런데 **이미 B 방식으로 739개 분류가 끝나 있다**(대화에서 분류해 SQL 로 전달, 사용자 보유).
  그 사전을 Supabase 에 넣으면 API 없이 돌아간다
- 작성·로컬 검증만 됐고 **한 번도 배포된 적이 없다.** 지금 화면에서 눌러도
  "AI 분류 함수가 아직 배포되지 않았어요" 가 뜨는 상태였다

## 고려한 선택지

### A. 배포해서 자동 분류를 살린다

새 엑셀을 올릴 때 모르는 장소가 자동으로 분류된다. 담당자가 손댈 일이 줄어든다.
대신 유료 API 키를 운영 환경에 두어야 하고, 분류 결과를 사람이 확인하는 절차가 따로 필요하다.
**한 번도 배포해 본 적 없는 경로라 운영 위험도 있다.**

### B. 꺼진 채로 코드만 남긴다

지금 상태. 아무 비용도 안 들지만 **작동하지 않는 코드 200줄**이 남는다.
더 나쁜 것은 **"자동 분류 AI 를 만들었다" 고 오해하게 만든다는 점**이다. 실제로 이번 대화에서
사용자가 "자동 분류 AI 를 새롭게 만들고 있었잖아?" 라고 물었고, 확인해 보니 자동 호출은 꺼져 있고
**학습 단계는 아예 없었다**(라벨은 사전에 저장될 뿐). 대외 공시·자기소개서용 정리에서 이 혼동이
반복해서 문제가 됐다.

### C. 지운다 ← **고름**

사전 기반이라는 **지금 실제로 돌아가는 구조**만 남긴다.

## 고른 이유

1. **유료 API 를 운영에 두지 않기로 했다**(사용자 결정, 2026-11-26)
2. **대안이 이미 작동한다** — 739개 사전이 만들어져 있고, 분류는 대화에서 하면 된다
3. **작동하지 않는 코드가 사실을 흐린다.** "AI 자동 분류"가 있다고 오해하게 만들었다
4. **지워도 되돌릴 수 있다** — git 역사에 남는다. 나중에 키가 생기면 이 커밋을 되살리면 된다

## 감수하는 것

- 새 엑셀에 처음 보는 장소가 나오면 **사람이 손으로 처리**해야 한다.
  절차는 인수인계의 "새 파일이 올 때" 절에 있다 — 검토표 CSV 를 내려 대화에 올리고,
  분류한 SQL 을 받아 `trip_places` 에 넣는다
- 되살리려면 코드를 다시 꺼내 **배포·키 설정을 처음부터** 해야 한다(한 번도 배포된 적이 없으므로
  그 작업은 어차피 남아 있었다)

## 함께 적어 두는 것 — "학습"은 없다

인수인계에 "지도학습 단계를 실제로 만들지" 가 미결로 남아 있다. **지금 구조에는 학습이 없다.**
`js/trip-*.js` 와 `tools/` 전체를 확인했다. 라벨은 사전에 저장될 뿐이고, 정확도를 재거나
분류기를 고치는 단계가 없다.

그래서 이 기능을 설명할 때 "자동 분류 AI" 가 아니라
**"AI 로 장소 사전을 만들고, 그 사전을 읽어 쓰는 규칙 기반 산정 시스템"** 이라고 말해야 맞다.

만든다면 `tools/trip.py sample` 로 뽑은 승차권 대조 표본이 **시험용 정답**이 될 수 있다 —
사람이 확인한 라벨로 분류 정확도를 재는 구조가 지도학습에 가장 가깝다.
